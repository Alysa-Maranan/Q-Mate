CORRECT BEHAVIOR
----------------

Animation is now SERVO-BASED, not TIMER-BASED:

❌ BEFORE (Timer-based):
   - Animation shows for X seconds (timer)
   - Hides after timer expires
   - Doesn't wait for actual servo close
   - May hide while servo is still moving

✅ AFTER (Servo-based):
   - Animation shows when servo opens
   - Stays visible while servo is moving
   - Polls servo status every 500ms
   - Hides ONLY when servo actually closes
   - Accurate to real servo state

═══════════════════════════════════════════════════════════════

HOW IT WORKS
------------

1. User triggers feed (manual or scheduled)
   ↓
2. Animation appears immediately
   ↓
3. Timer updates display (for user feedback)
   - Shows countdown
   - Shows progress bar
   - Shows percentage
   - BUT doesn't control when animation hides
   ↓
4. Browser polls servo status every 500ms
   - Checks: /api/feeder/animation
   - If active: true → Servo still open, keep showing
   - If active: false → Servo closed, hide animation
   ↓
5. When servo closes:
   - Servo bridge deletes animation_trigger.json
   - Browser detects: active = false
   - Shows 100% completion
   - Waits 1 second
   - Hides animation
   - Reloads page

TROUBLESHOOTING
---------------

❌ Animation hides too early (before servo closes)
   → Check console logs
   → Should see: SERVO OPEN until servo closes
   → If shows SERVO CLOSED early, servo bridge issue

❌ Animation stays forever (doesn't hide)
   → Check console logs
   → Should see: SERVO CLOSED eventually
   → If stuck at SERVO OPEN, servo bridge not deleting file
   → Check: storage\logs\animation_trigger.json
   → Should be deleted after feeding

❌ Timer reaches 0 but animation stays
   → This is CORRECT behavior!
   → Animation waits for actual servo close
   → Check console: should show SERVO OPEN
   → Will hide when servo closes
